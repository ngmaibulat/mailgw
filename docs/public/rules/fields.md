# Field reference

Every field a rule can match on. This list is generated by the gateway itself:

```bash
mailgw-go fields
```

Prefer that command to this page — it is the registry, and it tells you about
your build. A field name not in the registry is a **load-time error**, with a
suggestion for what you probably meant.

## connect

Available from the moment the peer connects.

| Field | Type | Meaning |
|---|---|---|
| `conn.remote_ip` | ip | peer IP address |
| `conn.remote_port` | int | peer TCP port |
| `conn.local_ip` | ip | local IP the peer connected to |
| `conn.local_port` | int | local TCP port |
| `conn.is_private` | bool | peer is in RFC 1918 / ULA space |
| `conn.is_loopback` | bool | peer is on the loopback interface |
| `tag.<name>` | string | a tag set by an earlier rule |

`conn.local_port` is how you write a rule that applies only to the submission
port.

## helo

Available once the client has greeted.

| Field | Type | Meaning |
|---|---|---|
| `helo.name` | string | name given in `EHLO`/`HELO` |
| `conn.tls` | bool | session is encrypted |
| `conn.tls_version` | string | negotiated version, e.g. `TLS1.3` |
| `conn.tls_cipher` | string | negotiated cipher suite |

`helo.name` is domain-shaped: `*` in a glob stops at a dot.

## mail

Available after `MAIL FROM`.

| Field | Type | Meaning |
|---|---|---|
| `mail.from` | string | envelope sender, empty for a null sender |
| `mail.from_local` | string | local part of the sender |
| `mail.from_domain` | string | domain of the sender |
| `mail.is_null_sender` | bool | `MAIL FROM:<>` |
| `mail.is_dsn` | bool | this message is a bounce |
| `mail.size_declared` | int | `SIZE=` parameter, `0` when absent |
| `mail.body` | string | `BODY=`: `7BIT` or `8BITMIME` |
| `mail.smtputf8` | bool | `SMTPUTF8` was requested |
| `auth.authenticated` | bool | the client completed AUTH |
| `auth.user` | string | authenticated username, empty when unauthenticated |
| `auth.mechanism` | string | `PLAIN` or `LOGIN` |
| `spf.result` | string | `pass` `fail` `softfail` `neutral` `none` `temperror` `permerror` |
| `spf.domain` | string | domain SPF was evaluated for — domain-shaped for globs |

`mail.size_declared` is what the client *claimed*, before the body arrived. Use
it to refuse an oversized message at `MAIL FROM` instead of after receiving it —
but note a client is not obliged to send it, so `msg.size` at `data` is the one
that is always true.

`mail.is_dsn` is what a rule uses to give bounces their own relay group.

SPF is the one message-authentication check answerable this early — it is a DNS
walk over the sender's domain and the peer's address and never looks at the
message — which is why a rule reading only `spf.*` refuses on the sender's own
`MAIL FROM` line instead of after a megabyte of `DATA`. `spf.domain` is the
envelope sender's domain, or the `HELO` name when the sender is null. See
[Message authentication](/config/msgauth).

::: warning `mail.requiretls` exists but is never set
It is in the registry and `check` warns if a rule reads it. `REQUIRETLS` is not
advertised, so no client can ask for it — advertising it would be a promise about
onward delivery this gateway does not keep.
:::

## rcpt

Evaluated once per recipient.

| Field | Type | Meaning |
|---|---|---|
| `rcpt.to` | string | the recipient being evaluated |
| `rcpt.local` | string | local part |
| `rcpt.domain` | string | domain — domain-shaped for globs |
| `rcpt.index` | int | 1-based position in this transaction |
| `txn.rcpt_count_so_far` | int | recipients accepted before this one |

## data

Available at end of `DATA`, when the whole message is known.

| Field | Type | Meaning |
|---|---|---|
| `msg.size` | int | message size in bytes |
| `msg.line_count` | int | lines in the message |
| `msg.received_count` | int | `Received:` headers — the hop count |
| `msg.has_attachment` | bool | at least one attachment part |
| `msg.mime_part_count` | int | MIME parts |
| `txn.rcpt_count` | int | total accepted recipients |
| `txn.rcpt_domains` | string list | distinct recipient domains |
| `header.<name>` | string list | values of the named header |
| `header_count.<name>` | int | how many times it appears |
| `attachment.filename` | string list | attachment filenames |
| `attachment.content_type` | string list | attachment MIME types |
| `attachment.md5` | string list | MD5 of each attachment's **decoded** bytes |
| `attachment.size` | int list | attachment sizes in bytes |
| `attachment.disposition` | string list | `attachment`, `inline`, … |
| `dkim.result` | string | `pass` if any signature verified, else `fail` `temperror` `permerror` `none` |
| `dkim.domains` | string list | `d=` of every signature that **verified** |
| `dmarc.result` | string | `pass` `fail` `none` `temperror` `permerror` |
| `dmarc.policy` | string | what the `From` domain published: `none` `quarantine` `reject` |

DKIM needs the body and DMARC needs the `From` header, so both are `data` facts
however early SPF was answered.

`dkim.domains` lists only signatures that **verified**. A `d=` on a broken
signature is a claim anybody can attach — matching on one would be matching on
the forger's choice of victim.

`dmarc.policy` is what the domain *asked* for; this gateway does not act on it.
Pair the two to write the policy yourself:

```yaml
policy:
  - name: refuse forged mail from domains that asked us to
    match:
      all:
        - {field: dmarc.result, op: eq, value: fail}
        - {field: dmarc.policy, op: eq, value: reject}
    then:
      - {action: reject, code: 550, enhanced: "5.7.1", message: "DMARC policy"}
```

::: tip The MIME walk is not free
`attachment.*`, `msg.has_attachment` and `msg.mime_part_count` need the message
re-read and its MIME structure parsed. That happens **only** when a rule actually
asks for one of them, or `attach.enabled` is set — so a configuration that never
mentions attachments pays nothing.

The same bargain applies to `spf.*`, `dkim.*` and `dmarc.*`: a rule reading one
turns its check on for every message, whether or not `msgauth:` says anything. A
`dmarc.*` rule turns SPF and DKIM on too, because DMARC is alignment over their
results. `mailgw-go check` says which checks are on and which a rule turned on.
:::

::: warning A check that did not run is *absent*, not `none`
`none` means the check ran and found no policy published. If the check never
ran, the field is missing — so `spf.result eq "none"` does **not** match a
gateway that never looked, and `spf.result exists` is how you ask whether there
is an answer at all.
:::

A part counts as an attachment when its disposition says so, **or it names a
file** — an `inline` part with a `filename` is an attachment, whatever it calls
itself. `attach.include_inline` widens this further to any non-text-body part.

## Reading the types

- **string list** — a plain leaf asks "does any element match?"; use `every` for
  "do they all?". See [Matching](/rules/matching).
- **ip** — works with `in_cidr` as well as `eq`.
- **Domain-shaped strings** (`rcpt.domain`, `mail.from_domain`, `helo.name`) use
  the dot-stopping glob dialect.
